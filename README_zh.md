# AIReader

**一款专注于快速、高效阅读的原生 Android AI 阅读助手。**

借助大语言模型，逐段提取长文本的重要信息，或对全文进行全面分析总结，让阅读更高效、理解更深入。

## 项目简介

AIReader 是一款面向**书籍、长文章及其他长文本**的 AI 辅助阅读工具。

如果你经常需要阅读大量文字，例如书籍章节、长篇文章或学习资料，可以将文本复制到 AIReader 中，借助自定义提示词和大语言模型，快速获取文章的关键信息与分析结果。

AIReader 主要提供两种阅读方式：

- **逐段提取重要信息点**：按照文本的段落结构提取关键内容，适合快速掌握书籍章节或长文章中的重要信息。
- **全文分析总结**：从整体角度分析文本，梳理主要内容、核心观点和重要结论，帮助理解全文。

你也可以创建自己的提示词，自由扩展阅读、分析、整理和学习方式。

AIReader 不绑定特定的大语言模型服务。既可以通过自行配置的 API 直接获取结果，也可以将整理好的提示词和文章复制到其他 AI 客户端中使用。

生成或粘贴的 Markdown 内容可以在应用内查看、编辑、保存，还可以转换为 HTML，在浏览器中阅读或借助浏览器的朗读功能**听书**。

## 核心功能

### 1. 逐段提取重点与全文分析

AIReader 内置 **5 个阅读提示词**，支持不同的长文本处理需求，包括：

- **逐段信息提取**：按文本结构提取重要信息点，减少阅读时遗漏关键内容的可能。
- **全文分析总结**：对整篇文本进行综合分析，帮助把握主要观点和整体内容。
- **其他阅读处理方式**：通过不同内置提示词，选择适合当前文本的分析策略。

内置提示词使用 Markdown 格式，支持查看、编辑、保存，以及恢复默认内容。

你还可以参照内置提示词的格式，添加不限数量的**自定义提示词**，例如用于知识整理、概念解释、内容归纳或其他个人阅读需求。

> AIReader 的分析结果由所使用的大语言模型生成，实际质量取决于提示词、输入内容和模型能力。重要信息仍建议结合原文核对。

### 2. 自动文章预处理

为了让模型更容易定位长文本中的具体内容，AIReader 会在发送请求前自动对文章进行预处理。

预处理功能包括：

- 为文章段落添加编号标记。
- 为识别出的标题添加编号标记。
- 按指定数量的自然段进行分组。
- 将处理后的文本与选定提示词组合，形成发送给模型的最终内容。

**默认每 3 个自然段作为一个分组。**

你可以在「文章预处理设置」中修改分组数量，支持 **1–100**：

| 设置值 | 处理方式 |
| --- | --- |
| `1` | 每个自然段单独成组 |
| `2` | 每 2 个自然段成组 |
| `3` | 每 3 个自然段成组（默认） |
| `5` | 每 5 个自然段成组 |

例如，较小的分组值适合需要更细致定位信息的场景；较大的分组值则可以减少分组数量。

### 3. 自定义大语言模型 API

AIReader 支持自行配置 **OpenAI 兼容的 Chat Completions API**。

主要功能包括：

- 保存多套相互独立的 API 配置。
- 自定义模型服务地址和模型名称。
- 安全保存 API Key。
- 配置模型支持的思考深度参数。
- 自定义网络超时及自动重试参数。
- 使用 SSE 流式接收模型回复。
- 在生成过程中停止请求。

API Key 使用 Android Keystore 相关机制加密保护。

AIReader 不提供内置的免费模型额度。模型服务的可用性、请求限制及费用由你自行选择的服务商决定。

### 4. 没有 API 也能使用

**没有大语言模型 API，也可以使用 AIReader 整理提示词和文本。**

操作方法：

1. 选择内置或自定义提示词。
2. 粘贴需要阅读的书籍章节或文章。
3. 根据需要调整文章预处理设置。
4. 点击 **「预览最终发送内容」**。
5. 复制生成的内容，粘贴到你使用的其他 AI 客户端中。
6. 在 AI 客户端获取分析结果。

这样，即使没有配置 API，也可以利用 AIReader 的提示词管理和文章预处理功能。

如果想让 AI 客户端返回的内容便于复制到 AIReader 的 Markdown 工作区，建议在提示词中增加：

````markdown
## 输出格式

请以 Markdown 格式输出，并将完整结果放在一个 Markdown 代码块中。
````

随后复制代码块中的 Markdown 内容，粘贴回 AIReader，即可继续预览、编辑或转换为 HTML。

> 使用外部 AI 客户端时，文本会由你手动提交给该客户端。请自行留意其隐私政策、输入长度限制和使用规则。

### 5. Markdown 阅读工作区

AIReader 内置 Markdown 工作区，用于查看和处理阅读结果。

当你点击「开始阅读」后，应用会向已配置的模型 API 发送请求，并将流式返回的内容显示在工作区中。

工作区支持：

- Markdown 编辑与预览。
- 复制阅读结果。
- 粘贴从其他 AI 客户端获得的 Markdown。
- 将 Markdown 转换为 HTML。
- 在应用内预览 HTML。
- 导出 HTML 文件。
- 使用外部浏览器打开 HTML。

因此，Markdown 工作区既能展示 API 直接生成的报告，也可以用于处理你从其他 AI 工具获得的结果。

### 6. 在浏览器中阅读或听书

这是 AIReader 一个特别实用的使用场景。

获得 Markdown 阅读报告后，可以通过 **「更多操作」→「浏览器打开」**，将内容转换为 HTML 并交给浏览器显示。

推荐尝试 **Microsoft Edge** 浏览器。

Edge 提供「大声朗读」（Read aloud）功能。在支持该功能的浏览器版本中，你可以：

1. 在 AIReader 中生成或粘贴 Markdown 阅读报告。
2. 通过「更多操作」选择「浏览器打开」。
3. 在 Edge 中打开转换后的 HTML 内容。
4. 使用浏览器的「大声朗读」功能播放文字。

这样就能将 AI 整理后的阅读报告当作听书内容，减少长时间盯着屏幕阅读的负担。

**注意：** 文本转语音由外部浏览器提供，并非 AIReader 内置 TTS。实际功能入口、语音及可用性取决于所安装的浏览器和版本。

### 7. 阅读历史

AIReader 会在本地保存阅读历史，方便以后重新查看阅读成果。

历史记录支持：

- 查看已保存的 Markdown 阅读报告。
- 查看或打开 HTML 阅读内容。
- 查看已保存的文章原文（如果保存时启用了该选项）。
- 查看当时实际发送给模型的最终内容（如果该条历史保存了请求快照）。
- 管理和清空全部阅读历史。

你可以根据自己的需要决定是否保存文章原文。

### 8. 界面与外观

- 原生 Android 应用。
- 基于 Jetpack Compose 和 Material 3。
- 底部四个导航页面：**阅读 · 提示词 · 历史 · 设置**。
- 支持浅色、深色和跟随系统主题。

## 使用方法

### 方式一：通过 API 直接阅读

1. 在「设置」中添加大语言模型 API 配置。
2. 在「提示词」中选择逐段信息提取、全文分析总结或自定义提示词。
3. 返回「阅读」，粘贴需要处理的长文本。
4. 根据需要设置文章预处理参数。
5. 点击「开始阅读」。
6. 在 Markdown 工作区查看模型返回的结果。
7. 根据需要编辑、复制、保存、导出，或在浏览器中打开阅读和朗读。

### 方式二：不配置 API，使用其他 AI 客户端

1. 选择提示词并粘贴文章。
2. 点击「预览最终发送内容」。
3. 复制最终内容，粘贴到其他 AI 客户端。
4. 获取模型生成的 Markdown 结果。
5. 将 Markdown 粘贴回 AIReader 工作区。
6. 在应用内预览，或转换成 HTML 后使用浏览器阅读、朗读。

## 安装

可以安装本仓库 GitHub Actions 构建的已签名 Release APK；如果项目另有公开分发渠道，也可从相应渠道获取。

Android 可能要求允许从当前来源安装 APK。覆盖升级需要保持相同的应用包名和签名身份，新版 `versionCode` 也须满足 Android 的升级要求。

当 Debug 使用独立的 `.debug` 包名后，**Debug 与 Release 可以在一台设备上并存**，两者的应用私有数据互相隔离。

## 构建

主要技术栈为 **Kotlin、Jetpack Compose、Material 3、Gradle、Room、DataStore 和 OkHttp**。

在已正确配置 Android SDK 与 JDK 的环境中，可使用项目自带的 Gradle Wrapper：

```bash
./gradlew assembleDebug
./gradlew assembleRelease
```

Release 构建需要通过环境变量提供签名凭据。项目的 GitHub Actions 工作流采用手动触发方式：

- **Debug**：开发测试 APK。
- **Release**：开启 R8 代码优化和资源缩减，验证已签名 APK，并单独保存 R8 mapping 文件。

### Release 安全签名

Release 工作流使用受保护的 GitHub Actions **`release` Environment**，需要配置以下 Environment Secrets：

| Secret | 用途 |
| --- | --- |
| `RELEASE_KEYSTORE_BASE64` | Base64 编码的发布签名密钥库 |
| `RELEASE_STORE_PASSWORD` | 密钥库密码 |
| `RELEASE_KEY_ALIAS` | 签名密钥别名 |
| `RELEASE_KEY_PASSWORD` | 私钥密码 |

另需在 Environment Variables 中配置 `EXPECTED_RELEASE_CERT_SHA256`，用于核对**签名证书的 SHA-256 指纹**，不是 Keystore 文件本身的 SHA-256。

签名密钥和密码不得提交到 Git。Base64 **只是编码，不是加密**。请保护 `release` Environment、主分支和发布标签；不要在日志、Issue 中公开签名材料或其他凭据。

## 项目说明

- **项目定位**：以书籍、长文章和其他长文本的辅助阅读为主要使用场景，支持逐段提取重点、全文分析及自定义阅读任务。
- **底部导航**：阅读 · 提示词 · 历史 · 设置。
- **隐私**：阅读历史和模型凭据保存在本地；用户通过 API 发起 AI 阅读时，文章和相关提示词内容会发送至所配置的模型服务端点。通过外部 AI 客户端使用时，数据处理遵循相应服务商的规则。
- **数据管理**：可选择是否保存文章原文，并管理或清空本地阅读历史。
- **开发流程**：建议在 `dev` 分支测试，确认正常后合并到 `main` 进行 Release 构建。
- **开发约定**：项目相关工程规范请参阅 [AGENTS.md](AGENTS.md)。
